# Братка · Bratka the Bot

Считает сообщения, показывает самых активных участников, помогает выбрать между вариантами и отвечает на вопросы через Groq.

**[Команды](#команды) · [Запуск](#быстрый-старт) · [Обновление](#обновление-старой-установки) · [Данные](#данные-и-восстановление) · [Разработка](#разработка)**

## Команды

| Команда | Что делает | Пример |
|---|---|---|
| `/ping` | Проверяет, отвечает ли бот | `/ping` → `pong` |
| `/top` | Показывает 10 самых активных пользователей сервера | `/top` |
| `/difficult_choice` | Выбирает один вариант из списка через запятую | `/difficult_choice choices:чай, кофе, какао` |
| `/ask` | Задаёт вопрос нейросети через Groq | `/ask question:Объясни рекурсию простыми словами` |

### Как это выглядит

Иллюстративные текстовые примеры; имена и счётчики условные.

```text
/top

1. alex — 128 сообщений
2. masha — 96 сообщений
3. nikita — 76 сообщений
```

```text
/difficult_choice choices:чай, кофе, какао

Мой выбор: какао
Вариантов: 3
```

`/ask` публикует вопрос и ответ в канале. Длинные ответы приходят несколькими сообщениями. Бот не хранит историю диалога.

## Быстрый старт

Нужны **Python 3.12**, токен Discord-бота и, для `/ask`, ключ Groq. Без ключа Groq остальные команды работают.

### 1. Подготовь Discord-приложение

1. Создай приложение в [Discord Developer Portal](https://discord.com/developers/applications).
2. В разделе **Bot** получи токен. Он понадобится в `config.json`.
3. Для установки на сервер используй scopes `bot` и `applications.commands`, права **View Channels** и **Send Messages**. Для ответов в ветках также нужно **Send Messages in Threads**.
4. Пригласи бота на свой сервер. Убедись, что настройки нужных каналов разрешают ему видеть сообщения и отвечать.

Привилегированные intents включать не требуется: бот считает события сообщений и не читает их содержимое. Slash-команды синхронизируются при запуске; после первой установки их появление может занять некоторое время.

### 2. Установи зависимости

```bash
git clone https://github.com/ID-Dester/Bratka_the_bot.git
cd Bratka_the_bot
python -m venv .venv
```

**Windows / PowerShell:**

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item config.example.json config.json
```

**Linux / macOS:**

```bash
.venv/bin/python -m pip install -r requirements.txt
cp config.example.json config.json
```

Если команда `python` отсутствует, используй `python3.12` на Linux/macOS или `py -3.12` на Windows для создания окружения.

### 3. Заполни конфигурацию

Открой `config.json`:

```json
{
  "token": "DISCORD_BOT_TOKEN",
  "groq_key": "",
  "groq_model": "llama-3.1-8b-instant"
}
```

| Поле | Назначение |
|---|---|
| `token` | Обязательный токен Discord-бота |
| `groq_key` | Ключ [Groq Console](https://console.groq.com/keys); пустая строка отключает `/ask` |
| `groq_model` | ID модели, доступной твоему аккаунту Groq; необязательное поле |

Модель по умолчанию сохранена из старой версии. Доступность зависит от аккаунта: при необходимости выбери другой ID из [списка моделей Groq](https://console.groq.com/docs/models). Ключи не добавляй в Git; `config.json` уже исключён через `.gitignore`.

### 4. Запусти

```powershell
# Windows
.\.venv\Scripts\python.exe main.py
```

```bash
# Linux / macOS
.venv/bin/python main.py
```

После сообщения «Братка подключён» проверь `/ping`. Для остановки нажми **Ctrl+C** и дождись завершения процесса: бот сохранит статистику. На Linux также обрабатывается `SIGTERM`.

## Обновление старой установки

1. Останови старый процесс. У старой версии нет сохранения при выходе, поэтому дождись сообщения об автосохранении перед остановкой.
2. Сохрани отдельную копию `config.json` и `users.json`.
3. Обнови код и создай чистое виртуальное окружение: прежний список зависимостей содержал лишние пакеты.
4. Положи существующие `config.json` и `users.json` рядом с `main.py`. Формат статистики и старые поля конфигурации совместимы; поле `groq_model` добавлять необязательно.
5. Установи зависимости и запусти бота по инструкции выше.

Файлы теперь ищутся **рядом с `main.py`**, независимо от того, из какой папки запускается процесс.

## Данные и восстановление

- В `users.json` хранятся ID серверов, ID пользователей и число полученных сообщений. Тексты обычных сообщений не сохраняются.
- Сообщения ботов и личные сообщения не участвуют в рейтинге.
- Счётчик обновляется только во время работы бота; история сервера не загружается, удаление сообщения не уменьшает счётчик.
- Вопрос `/ask` передаётся Groq. При ответе в канале вопрос и ответ видны участникам с доступом к этому каналу.
- Каждые пять минут и при штатной остановке статистика записывается через временный файл, `fsync` и атомарную замену. `users.json.bak` содержит предыдущий корректный снимок.
- При повреждённом JSON запуск прекращается с ошибкой. Исходный файл остаётся на месте.

**Восстановление:** останови бота, сохрани повреждённый файл отдельно, проверь содержимое `users.json.bak`, затем скопируй его в `users.json` и запусти бота снова. Не удаляй повреждённый файл до проверки резервной копии.

**Ограничения:** запускай только один процесс на один файл статистики. При аварийном завершении могут потеряться сообщения после последнего сохранения. Резервная копия на том же диске не защищает от поломки диска.

## Ограничения `/ask`

- До 1000 символов в вопросе.
- Один запрос от пользователя раз в 10 секунд.
- До двух одновременных запросов на весь процесс; дополнительные запросы получают ответ «попробуй позже».
- Тайм-аут запроса SDK — 30 секунд, общий предел ожидания — 35 секунд; автоматические повторы отключены.
- Генерация ограничена 1024 токенами. Собственные лимиты и доступность моделей определяет Groq.

## Разработка

```bash
python -m pip install -r requirements.txt
python -m pip check
python -m unittest discover -s tests -v
```

Используй Python своего виртуального окружения. Тестам не нужны токены: Discord и Groq подменяются тестовыми объектами. GitHub Actions выполняет проверки на Python 3.12 в Windows и Linux.

```text
main.py                 Команды, конфигурация и жизненный цикл бота
storage.py              Проверка и атомарное сохранение статистики
config.example.json     Пример настроек без секретов
requirements.in         Две прямые зависимости
requirements.txt        Зафиксированное окружение исполнения
tests/test_bot.py       Проверки ошибок и основных сценариев
.github/workflows/      Автоматические проверки
```

Для обновления зависимостей создай отдельное чистое окружение, установи `requirements.in`, выполни тесты и сохрани `python -m pip freeze` в `requirements.txt`. Изменения зависимостей проверяй на обеих ОС в CI.
